# v0.3 验证记录

## 可复现的功能检查

- `node --test tests/*.test.js`：29 项通过，覆盖时间同步、缺失/置信度、原/增强结果切换所依赖的数据契约、未预测脚掌/手指隐藏、模型错误与成功任务的收尾。
- `python3 -m unittest discover -s tests -p 'test_*.py'`：5 项通过，覆盖左右关节映射、横竖视频坐标尺度、合成关节置信度、缺失帧与输入验证。
- `python3 -m py_compile scripts/*.py`：通过。
- 本地 API 拒绝外站 Origin（403）及无效/空序列（400）。

这些检查验证程序行为，不衡量动作还原准确率。

## 本机模型试跑

Apple Silicon Mac、MPS、MotionBERT Lite 作者发布的 H36M global fine-tuning 权重。使用本地 720 × 1280 舞段前 12.1 秒，共 363 个 30 Hz 检测帧。视频包含镜墙、背身动作和宽松衣服。素材及姿态坐标不进入仓库。

- 本地推断成功，独立进程冷启动和推断共约 15 秒；该数字不能保证其他视频或电脑的耗时。
- 查看原机位、侧面以及抬腿/举手时的两种输出。时序输出改变了侧面腿部的前后关系；单条视频没有真实三维坐标，无法判定变化的准确程度。
- 在两端关节的原始检测置信度均 ≥0.55 的帧上，八条四肢骨段的平均变异系数（长度标准差 / 均值）由基础模型原始 3D 输出约 0.147 变为时序模型约 0.106。这仅描述骨长稳定性，不是位置误差，也不是准确率提升百分比；默认画面对齐另会改变基础模型骨长。
- 时序模型训练骨架只有 17 点，头顶来自近似映射；输入仍依赖 MediaPipe 检测。没有独立多机位或真实三维标注，不应把此试验版作为准确重建的证据。

## 仍需验证

多种舞姿和拍摄条件下的真实三维误差、转身朝向、严重遮挡、快速动作及学习效果。当前保留基础与时序两种模式供逐段对照。

## 完整片段页面验收

本地 65.6 秒舞段（1968 帧）已完成基础分析及完整序列增强。页面可切换两种三维输出，增强时画面对齐禁用，切回基础时恢复；取消增强后基础分析仍可使用。检查了原机位、侧面、背面及时间轴定位；视频处理和播放验证保持静音。CPU 分支也以 30 帧序列完成一次真实模型推断。

轨迹现在按各关节置信度独立中断，隐藏脚踝不再清空可靠的手腕轨迹；全身位置突变仍中断全部相关轨迹。
