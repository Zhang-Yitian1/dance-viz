# 舞迹 / Dance Trace

单机位短舞段的本地动作观察 Demo。原视频和估计三维姿态共用视频时间轴，支持慢放、A–B 循环、多角度查看、手腕与脚踝轨迹、肩胯辅助线及同步镜像。

## 运行

要求 Python 3.10+、支持 WebGL 的现代桌面浏览器。推荐先用 10–20 秒的单人全身、固定机位、光线清晰视频。

```bash
python3 scripts/serve.py
```

打开 http://127.0.0.1:8765 ，选择 ≤90 秒视频，点击「分析动作」。Mac 上也可在 Finder 中双击 `start.command`。启动脚本会自动检查并补齐模型与依赖；首次下载需要联网，此后可断网运行。

**使用期间必须保持启动窗口打开。** 关闭窗口或按 Ctrl+C 会停止服务；浏览器可能仍显示已载入的页面，但新的模型加载会失败。重新运行启动脚本后再点击分析即可；老版本页面可能需要刷新并重新选择视频。启动脚本固定使用自身所在的项目目录，避免从错误目录提供网页。

视频使用浏览器本地对象 URL，视频文件不发送给服务器，也不会提交到 GitHub。时序增强仅将二维关节坐标发送到同机的本地服务。MOV 能否播放取决于视频编码；无法解码时请先转换成 H.264 MP4。

## 时序三维增强（试验）

新增可选的 MotionBERT Lite 三维姿态推断：先在浏览器分析二维关节，再利用连续多帧估计三维姿态。它与基础 MediaPipe 三维结果可直接切换，便于检查侧面手脚、转身和肩胯关系；不保证每个动作更准。

额外要求 Python **3.10–3.13**，推荐 Python 3.12；PyTorch 2.8.0 与 NumPy 2.2.6 在项目自己的虚拟环境中安装。Apple Silicon 使用 MPS，其他设备使用 CPU。首次安装需联网下载依赖与约 64 MB 的作者发布权重；安装后推断完全在本机进行。

```bash
python3.12 scripts/setup_motion.py
python3 scripts/serve.py
```

安装期间约需 1 GB 磁盘空间。准备完成后刷新页面，选择视频并「分析动作」，再点击「增强三维」。增强完成后「三维方式」可切换基础 / 时序增强。可取消增强；失败或取消时保留已完成的基础分析。视频默认静音，可通过「播放原视频声音」自行开启。

视频文件仍仅由浏览器读取。增强时只将二维关节坐标发送到同机的 `127.0.0.1` 服务，由独立本地进程推断；不会发送到互联网，不保存视频或姿态数据。服务每次只运行一个增强任务，支持取消和超时终止；最新结果暂存内存，15 分钟后读取过期，下次增强或服务退出时释放。

时序模型采用 H36M 的 **17 点身体骨架**，由 MediaPipe 二维结果转换；头顶位置近似，脚掌、手指不由该模型预测，因此增强视图隐藏相关细节。低置信度关节仍隐藏，缺失帧不显示补造的动作；短缺失仅提供内部上下文，长跟踪中断会分段。推断采用重叠窗口减少接缝，每段最长 243 帧。

增强模式使用模型自己的三维坐标，不再用「画面对齐」逐点覆盖横纵位置，以免改变身体比例。整段采用一个人体尺度，躯干长度按假设值归一化，并非量出的真实身高。胸廓与骨盆分别按肩线、胯线显示，便于观察相对扭转。

**仍是单目估计，尚未验证真实三维准确率。** 训练数据与舞蹈、宽松衣服、背身动作存在差异，遮挡、错误的二维检测和前后方向歧义仍会影响结果。功能测试、骨长更稳定或投影更贴合都不能证明三维还原准确；请对照原视频和两种模型结果。

## 三维对齐与同步

默认「画面对齐」使用二维关节相对骨盆的画面位置约束三维横向、纵向坐标，三维深度仍采用模型估计。正交相机避免估计深度再次放大、缩小前视图中的手脚位置；可关闭此选项对比原始三维输出。缩放与人体大小会改变，原机位方向下的关节相对位置遵循二维结果。

**这只是投影一致性修正，不是准确三维重建。** 没有相机标定或真实三维数据，侧面、背面、骨长与深度仍可能错误；二维检测错误也会进入对齐结果。肩胯无法可靠检测时暂用原三维估计。

分析采样由 20 提高到 30 帧/秒；二维、三维骨架按相同视频时间插值，低置信度关节不插值显示。离线三维平滑使用前后帧对称滤波，取消单向平滑引入的拖尾；模型内部跟踪仍可能存在延迟。更多采样会增加分析时间。

## 手脚位置不对时

1. 先看原视频上叠加的点：橙色为手腕，蓝色为脚踝。如果这些点就不贴合人体，三维换角度无法修复定位错误。
2. 视频有镜子或倒影时，点击「定位舞者」，在视频开头点击实际舞者的胸腹位置，再分析。默认使用单人检测；指定舞者后检测最多三个候选，并按躯干位置连续选择一位舞者；这不是多人动作展示。候选顺序改变时继续跟踪，目标缺失或匹配含糊时标记中断。复杂倒影和严重遮挡仍可能选错或漏识别。
3. 可切换 Full / Heavy 后重新分析同一片段。Heavy 需要更多计算，不保证每个舞姿都更准确；保留 Full 为默认。启动时会补齐两个官方模型。

原视频和三维人形都隐藏低置信度的关节及其连线，三维位置明显突变时隐藏该帧。**隐藏错误不等于还原准确，高置信度点也可能出错。** 被遮挡的手脚暂不补造动作。一次选择的位置只指导视频开头的目标识别，重新导入视频会重置。

## 实际能力和边界

- 使用 MediaPipe Pose Landmarker Full / Heavy 模型输出 33 个身体关键点，约每秒采样 30 帧。GPU 初始化失败时尝试 CPU。处理耗时取决于设备与视频，未承诺实时速度。
- 三维姿态属于单目估计；旋转后的画面不是实际多机位拍摄。遮挡、快速转身、深度与肩胯的细微扭转可能估计错误。
- 三维展示以骨盆为中心，保留朝向，但**不恢复舞者在地面的全局移动轨迹**。三维手脚轨迹是相对身体的路线；原视频叠加轨迹保留画面内的位置变化。
- 缺失姿态不回填；被遮挡、出画、明显位置突变会标记在时间轴上。提示只反映检测到的异常，不代表未标记的姿态一定正确。轨迹按各关节置信度分别中断；隐藏脚踝不会清空可靠手腕的轨迹。平滑仍在异常处断开。
- 半透明人形由关节与几何体构成，用于动作观察，不是精确人体表面重建。第一版不提供手指细节、自动教学拆步、动作打分、多人跟踪、自动剪辑和云处理。

## 开发与测试

不需要打包器或 npm install。网页采用 ES modules；请使用 HTTP 服务，不能直接双击 HTML。

```bash
node --test tests/*.test.js
python3 -m unittest discover -s tests -p 'test_*.py'
```

`src/core.js` 管理时间采样、异常检测和平滑；`src/subject.js` 管理舞者选择与连续匹配；`src/app.js` 管理视频分析及同步交互；`src/renderer.js` 管理三维显示。原始检测帧和显示帧分别保留在浏览器运行时，刷新页面即释放；增强服务内存行为见上文，不落盘保存视频或姿态数据。

`vendor/` 由下载脚本生成且不进版本库。依赖锁定为 Three.js 0.180.0（MIT）和 MediaPipe Tasks Vision 0.10.14（Apache-2.0）。下载脚本校验 npm 包的发布 SHA-1。模型使用 Google 官方 pose_landmarker_full/float16/1 与 pose_landmarker_heavy/float16/1 文件。仓库原创代码采用 MIT 许可。`third_party/motionbert/` 保留作者 Apache-2.0 许可与版权说明，来源固定为 [MotionBERT 官方仓库](https://github.com/Walter0807/MotionBERT/tree/705d3a95354db8bdb696b3492e47a3b5537174ff)。增强权重来自 [作者 Hugging Face 仓库](https://huggingface.co/walterzhu/MotionBERT/tree/370a919/checkpoint/pose3d/FT_MB_lite_MB_ft_h36m_global_lite)，单独下载且 SHA-256 校验，不进入 Git。依赖及模型的条款按各自官方说明执行。

## 迭代方向

1. 用真实舞段记录遮挡、转身和快速动作的失败情况，验证学习效果。
2. 优化长片段处理、模型下载诊断与异常呈现。
3. 评估更完整的三维恢复方法与全局位移，接入前明确算力需求和实际准确性。

初版重点是可运行与可验证；尚未证明它能够准确还原任意舞蹈。
